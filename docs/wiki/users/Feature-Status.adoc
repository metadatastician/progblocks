== Why this page exists

`README.md` lists what ProgBlocks does. This page is the single place that
states, per feature, what is actually true and how strongly it is known,
with a pointer to the evidence. It is drawn from reading `src/` and from
the test suite, and must be updated whenever the underlying code changes —
if this table and the code disagree, trust the code and file an issue
against this page.

[IMPORTANT]
====
Status as of 2026-10-05, branch `feat/render-core-variants-vars`. "Works"
below means implemented **and** covered by the automated suite
(`bun test`, under happy-dom). The demo page has also passed an axe-core
audit in headless Chromium (`just a11y`); nothing has been checked with a
screen reader. Earlier history: `src/prog-block.js` once had a
fatal import bug that kept the element from registering at all; that was
fixed and is guarded by `tests/registration.test.js`, and the file now
imports nothing.
====

== Status table

[cols="3,1,4",options="header"]
|===
|Feature |Status |Evidence

|Custom element registers
|Works
|`tests/registration.test.js`.

|Variant tabs (`<template data-variant>`)
|Works
|One tab per template; WAI-ARIA tabs pattern (roving `tabindex`,
`aria-controls`/`aria-labelledby`, ArrowLeft/Right with wrap, Home/End,
automatic activation); `variant` attribute/property picks the variant;
`label` names the tablist; a single variant shows no tablist. Tabs are
generic labels — no platform detection. Tests: `variant switching` group.

|Cross-block sync (`group="…"`)
|Works
|Blocks sharing a group switch together. Page-local and in memory only —
not persisted across page loads (`DEBT.adoc` C15).

|`{{ name }}` / `{{ name = default }}` substitution
|Works
|One labelled input per variable across all variants; values persist
across variant switches; typing keeps the same `<input>` and focus; unset
variables show `{{ name }}` styled as unset. A plain regex, not the A2ML
parser. An empty value means "unset" and shows the default or
placeholder (`DEBT.adoc` C4). Tests: `variable substitution` group.

|Copy button
|Works
|Copies the personalised text (`block.text`) via `navigator.clipboard`
and announces the result in a `role="status"` region. Tested with a
stubbed clipboard; the failure path is untested.

|Line numbers
|Works
|`line-numbers` attribute; gutter is `aria-hidden` and
`user-select: none`, and Copy never includes it. No UI toggle.

|Events and script API
|Partial
|`progblocks:variant-change` and `progblocks:variable-change` (bubbling,
composed), `variant`, `text`, `getVariable()`, `setVariable()`. Only the
`variable-change` event has a test; `variant-change` fires only for a
change the reader makes in that block.

|Safe rendering of untrusted content
|Works
|All author and reader text reaches the shadow tree via `textContent`; no
`innerHTML` in `src/`. Unescaped tags inside a `<template>` are dropped,
not rendered. Tests: `untrusted content is never rendered as markup`.

|"Inject anywhere" embedding
|Works (happy-dom only)
|The stylesheet URL is resolved with `new URL('./prog-block.css',
import.meta.url)`, so the host page can live at any depth. Tested from a
page at `/docs/deep/`; not yet checked in a real browser. See
link:Getting-Started.adoc[Getting Started].

|Reacting to light-DOM changes after first connect
|Absent
|Content is read once; later edits to the templates are ignored
(`DEBT.adoc` C14).

|Syntax highlighting
|Absent (out of scope)
|Exposes `class="language-…"` on `<code>` and `::part()` names for a host
highlighter; no highlighter integration has been tried (`DEBT.adoc` C16).

|Accessibility — WCAG 2.1 AA target
|Audited, not screen-reader tested
|Tabs pattern, labelled inputs in a fieldset, live region, focus-visible
rings, `forced-colors` support, no opacity-dimmed tabs, focusable code
panel. Structure unit-tested; axe-core in headless Chromium (`just a11y`)
reports 0 violations with contrast checked; no screen-reader session yet. See link:../developers/Accessibility.adoc[Accessibility].

|Accessibility — AAA conformance tier
|Absent
|The top WCAG conformance tier is not met, despite historic claims
elsewhere in the estate. See
link:../developers/Accessibility.adoc[Accessibility] for the explicit
statement.

|A2ML variable parser (tree-sitter)
|Absent / stub
|`assets/tree-sitter-a2ml.wasm` is a 118-byte ASCII placeholder file
(literally reads "// Dummy WASM file placeholder"), not compiled
WebAssembly. The tree-sitter load path in `src/a2ml-parser.js` is
commented out, and nothing imports the module.

|K9 / Nickel validation
|Absent / stub
|`validateNickel()` fakes a 50 ms `setTimeout` then unconditionally
returns `{valid: true, errors: []}`; `executeJustTask()` logs and
returns `true`. Nothing imports `src/k9-validator.js`.

|Preview toggle (code view vs. live preview view)
|Absent
|Never implemented; no longer advertised in `README.md`.

|Templating wizards
|Absent
|No storage, no forms, no wizard code anywhere in the repository; no
longer advertised.

|Inline code editing (`contenteditable`)
|Removed 2026-10-05
|Out of charter. It also destroyed `{{ variable }}` placeholders when

|Live linter

|Split view (side-by-side / top-bottom)
|Removed 2026-10-05
|Out of charter. It was never wired to the host attribute its CSS used.

|Smart paste (array / matrix / text detection)
|Removed 2026-10-05
|Out of charter; `src/modules/smart-paste.js` and its tests deleted.

== Legend

* **Works** — implemented and covered by the automated suite (under
  happy-dom), no known defect blocking normal use. Not a claim of
  real-browser verification.
* **Partial** — the feature exists and does something, but has a
  real defect, a test gap, or a materially narrower scope than
  described.
* **Broken** — code exists for the feature but it does not function
  (wired incorrectly, hardcoded stub output, or destroyed by another
  code path).
* **Absent** — no implementation exists.
* **Removed** — existed in an earlier revision and was deliberately
  deleted as outside the component's charter.
