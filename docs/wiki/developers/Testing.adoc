== Running the suite

[source,bash]
----
just test
# or, equivalently (this is what CI runs):
bun run test
# or, directly:
bun test
----

The `Justfile`'s `test` recipe is:

[source,make]
----
test:
	bun test
----

**This gate can fail honestly.** The recipe used to be `node --test
tests/ || echo "No tests configured yet"`, whose `||` clause made the
exit code always `0` regardless of whether the tests underneath passed
or failed. That fallback was removed; the runner has since moved from
`node --test` to `bun test`, and `bun run test` (via `package.json`)
runs the same command.

== What the suite covers

Five test files, 49 tests, all passing as of 2026-10-05. The DOM comes
from happy-dom, registered once by `tests/helpers/dom.js` with a page URL
of `/docs/deep/page.html` so that path-resolution bugs show up.

* `tests/jcs.test.js` (10 tests) — `tools/jcs.mjs`: the RFC 8785 §3.2.3
  sample reproduced exactly, UTF-16 member ordering, ECMAScript number
  output, and rejection of I-JSON violations (duplicate names, lone
  surrogates, out-of-range numbers, trailing content).
* `tests/component.test.js` (32 tests) — the component's behaviour:
** *untrusted content is never rendered as markup* — escaped and
   unescaped markup in templates, markup typed into a variable input,
   markup in a tab label;
** *variable substitution* — the same `<input>` survives typing, unset
   placeholders, inline defaults, values persisting across variants,
   every input labelled, the `progblocks:variable-change` event;
** *variant switching* — the WAI-ARIA tabs attributes, arrow/Home/End
   keys with wrap, the `variant` attribute, `group` sync, the
   `progblocks:variant-change` event, single-variant rendering;
** *embedding* — stylesheet URL resolved against the module, copy
   writing the personalised text and announcing it (clipboard stubbed),
   download saving it under the `filename` attribute,
   line-number count and `aria-hidden`;
** *remembering the reader's variant* — with `group` and `persist` a
   reader choice is stored in `localStorage` and restored on the next
   mount; without `persist` nothing is stored; a remembered name the
   block lacks falls back to the first variant; a throwing
   `localStorage` leaves switching working; another tab's `storage`
   event is followed without echo, and unrelated keys are ignored;
** *authored content that changes after render* — replacing templates
   re-renders while keeping the variant and reader values; plain-text
   edits are picked up; `refresh()` picks up edits inside
   `template.content`; a burst of mutations triggers one rebuild;
** *pure helpers* — `dedent()` and `tokenize()`.
* `tests/registration.test.js` (1 test) — imports `src/prog-block.js` and
  asserts `customElements.get('prog-block')` is defined and that a
  constructed `<prog-block>` is a real `HTMLElement` instance.
* `tests/ci-config.test.js` (4) and `tests/dependabot-config.test.js` (2)
  — guard the CI and Dependabot configuration, not the component.

`tests/prog-block.test.js` (smart-paste parsing) was deleted on
2026-10-05 together with `src/modules/smart-paste.js`.

== A bug this suite used to miss — and how that was fixed

Until PR #18, nothing imported `src/prog-block.js`, so the module
graph was never exercised by tests. `src/prog-block.js` carried a
named-import mismatch (`import { validateK9 }` against
`k9-validator.js`, which exports only `K9Validator` and
`defaultValidator`) — a link-time `SyntaxError` that kept
`customElements.define('prog-block', …)` from ever running. The
component was completely inert on every page that loaded it, and the
(then single-file) test suite still passed, because it never touched
`prog-block.js` at all.

The import was fixed, and `tests/registration.test.js` was added
specifically to catch this class of regression. Since 2026-10-05
`src/prog-block.js` imports nothing.

== What the suite does NOT cover — and why that matters

* **A real browser.** happy-dom does not do layout, real focus
  rendering, an accessibility tree or a real clipboard. Every "works" in
  link:../users/Feature-Status.adoc[Feature Status] means "works under
  happy-dom".
* **Screen-reader verification** — none. The axe-core audit (`just a11y`)
  runs in a real Chromium; it is not part of `bun test`, but CI's
  `build` job runs it. See
  link:Accessibility.adoc[Accessibility].
* `glyph-mode` rendering, the
  copy-failure path, and attribute changes after first render
  (`attributeChangedCallback()`).
* Coverage is not measured.
* `k9-validator.js`'s stub methods — the module is not imported by the
  component. (The A2ML parser stub, `src/a2ml-parser.js`, was deleted on
  2026-10-05.)

A passing `bun test` means the component registers and that the
behaviours listed above hold under happy-dom — nothing more.

== Package manifest state

`package.json` and lockfiles exist in the repository root. CI installs
the two dev dependencies (`happy-dom` and `@happy-dom/global-registrator`)
with `bun install --frozen-lockfile` from `bun.lock`.
