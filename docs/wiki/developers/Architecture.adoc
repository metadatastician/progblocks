== Render model, and why it is a problem

`ProgBlock` keeps a single `_state` object (variants, active variant
id, a `Map` of A2ML variables, language, line-number flag, split-view
mode, linter state). Every mutation goes through `updateState()`:

[source,javascript]
----
updateState(newState) {
  this._state = { ...this._state, ...newState };
  this.render();
}
----

`render()` does not do incremental DOM updates or diffing of any kind.
It builds one large template string covering the tabs, the variable
panel, the line-number gutter, the editable code area, and the linter
panel, then assigns the whole thing in one shot:

[source,javascript]
----
this.shadowRoot.innerHTML = `...`;
this.bindEvents();
----

This is a full shadow-root teardown and rebuild on **every** state
change, including a single keystroke in a variable `<input>` (via
`handleVarChange()` → `updateState()`) or in the `contenteditable`
code area (via the `input` listener → direct state mutation, which
does not even call `render()` for that path, but does for others that
share the same underlying DOM).

Consequences, in order of severity:

1. **Focus loss.** Editing a variable input triggers
   `updateState()` → `render()` → a fresh `shadowRoot.innerHTML`
   assignment. The `<input>` the user was typing into is destroyed and
   a new one created in its place. The new element is not focused, so
   in a real browser, typing more than one character into a variable
   value is not reliably possible — each keystroke loses focus.
2. **No event-listener lifecycle management.** `bindEvents()` is
   called after every render and re-attaches listeners to the freshly
   created nodes; the old nodes (and their listeners) are simply
   discarded along with the rest of the shadow root. This works, but
   only because the rebuild is total — there is no partial-update path
   to get subtly wrong, because there is no partial update at all.
3. **XSS surface.** Because rendering is template-string
   interpolation into `innerHTML`, and variant content is read via
   `t.innerHTML` in `parseLightDOM()` and variable values are
   interpolated unescaped into `value="${val}"` in `render()`, there is
   no HTML-escaping anywhere in the pipeline. For a component whose job
   is rendering documentation snippets — plausibly containing HTML
   examples, or variable values that came from a query string or CMS
   field — this is a live injection surface, not a theoretical one.
   Tracked for a `fix/render-security` pull request; not fixed at the
   time of this review.

A structural fix (virtual-DOM diffing, or at minimum re-rendering only
the changed sub-tree and never re-creating a focused element) is not
present in any branch as of this review.

== Dead code

`src/modules/view-manager.js` (`ViewManager` class: `setSplitView()`,
`toggleLineNumbers()`, `attachLinterPanel()` with real WebSocket
handling) is never imported by `prog-block.js` or anything else in the
repository. It represents the intended real implementation of the
linter panel and split-view control, neither of which the shipped
component actually uses.

`src/a2ml-parser.js`'s `A2MLState` class (a pub/sub variable store) is
likewise never instantiated anywhere.
