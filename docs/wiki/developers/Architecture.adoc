== Module map

nothing. Two dev dependencies, `happy-dom` and
`@happy-dom/global-registrator` (see `package.json`), provide the DOM for
the test suite, which runs under `bun test`. ESM throughout. Line counts
below are approximate (2026-10-05; the component file was still being

== Render model

`ProgBlock` builds its shadow tree **once**, on first connect, and then
patches it in place; it rebuilds only when the authored light DOM
changes (step 5). It never assigns `innerHTML`.

1. `connectedCallback()` runs `_readLightDom()` (reads each
   `template[data-variant]`'s `content.textContent`, dedents it, and
   tokenises it into text and `{{ variable }}` segments) and `_build()`
   (creates the header and tablist, the variable fieldset, the gutter,
   the code panel and the status region with `createElement`). A
   `_built` flag stops this running again. With `persist` and `group`
   both set, a variant name remembered in `localStorage`
   (`progblocks:variant:<group>`) is selected first, ahead of the
   `variant` attribute; every storage access is in `try`/`catch`.
2. Switching variant calls `_renderVariant()`, which updates
   `aria-selected`, the roving `tabindex` and `aria-labelledby`, and
   replaces only the children of `<code>` with fresh text nodes and
   variable `<span>`s.
3. Typing in a variable input calls `setVariable()`, which updates only
   that variable's `<span>`s via `textContent` (`_renderValues()`) and the
   line-number gutter if the line count changed. The `<input>` itself is
   never replaced, so focus and caret survive.
4. Observed attributes (`variant`, `line-numbers`, `language`, `group`)
   are applied as targeted patches in `attributeChangedCallback()`.
5. A `MutationObserver` on the host (`childList`, `subtree`,
   `characterData`, and the `data-variant` attribute) calls
   `_scheduleRefresh()`, which coalesces a burst of mutations into one
   `refresh()` per microtask. `refresh()` (public) re-reads the light
   DOM, replaces the shadow tree via `_build()`, and restores the
   selected variant by name and the reader's values. The observer
   disconnects in `disconnectedCallback()`. Edits to a template's
   `.content` fragment are invisible to observers; the host calls
   `refresh()` after one.

Consequences:

* **No markup injection.** Every piece of author or reader text —
  code, tab labels, variable names and values — goes in via
  `textContent` or attribute setters. Tests:
  `tests/component.test.js` › `untrusted content is never rendered as
  markup`.
* **Focus is stable.** Test: `typing keeps the same input element and
  updates the code in place`.
* **Listeners are attached at build time**, to nodes that live until the
  next rebuild (step 5) or the element's removal.
* ~~**Light-DOM changes after first connect are ignored**~~ — observed
  since 2026-10-05 (`DEBT.adoc` C14, cleared). The cost: a rebuild
  replaces the variable inputs, so focus inside the block is lost when
  the authored content changes. Tests: `authored content that changes
  after render`.
* **Persistence is opt-in and minimal**: only the variant name, only
  with `persist`, only for reader-initiated selections; other open
  tabs follow via the `storage` event, without echo. Tests: `remembering the reader's variant`.

All of this is unit-tested under happy-dom. Checked once by hand in headless Chromium on 2026-10-05: persist
survived a reload, group sync and arrow keys worked, and a live template
swap kept the variant and typed value. It has not been profiled.

== Unused code

None in `src/`. The unimported stubs `src/a2ml-parser.js` and `src/k9-validator.js` were deleted
on 2026-10-05 and 2026-10-06, and `contracts.ncl` with them on 2026-10-06.
The variable syntax the component actually supports is defined by `tokenize()` in `src/prog-block.js`.
